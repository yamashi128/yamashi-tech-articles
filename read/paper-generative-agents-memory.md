# Generative Agentsを読む：AIの記憶を、次の行動につなぐ設計

[掲載ページ](https://yamashi-tech.com/articles/paper-generative-agents-memory) · [原稿データ](../articles/paper-generative-agents-memory.json)

公開: 2026-09-17 / 更新: 2026-10-23 / 確認: 2026-10-23

25体のエージェントが暮らす街を支えたのは、記憶の検索・振り返り・計画だった。必要な過去を選ぶ仕組みと、人間らしさを測った比較実験を解説する。

## 長く動くAIには、必要な過去を取り出す仕組みがいる

Generative Agentsが示したのは、経験を全部プロンプトへ詰め込まず、今の判断に必要な記憶を選び、そこから予定を作る設計だ。過去の出来事を保存するだけでなく、検索、振り返り、計画を組み合わせることで、時間をまたいだ行動の一貫性を作った。

研究の舞台は、25体のエージェントが暮らす仮想の街だ。ある住人へパーティーを開きたいという設定を与えると、会話で招待が広まり、予定を合わせて集まる振る舞いが観察された。見どころは街のにぎやかさに加え、以前に聞いた話を後の行動へつなげる仕組みにある。

## 記憶は、新しさ・重要さ・関係の深さで選ぶ

記憶は自然言語の出来事として保存し、作成時刻と最後にアクセスした時刻を持たせる。検索では、最近取り出した記憶か、重要な出来事か、現在の状況に意味が近いかという三つのスコアを使う。それぞれを正規化し、論文の実装では同じ重みで合計した。

新しさは仮想時間の1時間あたり0.995で減衰し、重要さはモデルが1〜10で評価する。関係の深さには埋め込みベクトルのコサイン類似度を用いた。単に新しい記録を選ぶと大切な約束を忘れ、意味の近さだけなら何度もした雑談が優先される。この三項は、何を覚えておくべきかを別々に調整できるようにする。

論文の検索スコアを簡略化した概念式

```text
検索スコア = 正規化した新しさ
           + 正規化した重要さ
           + 正規化した現在の状況との関連度

スコアの高い記憶から、入力に収まる範囲を選ぶ
```

## 出来事をまとめ、未来の予定へ変える

個別の出来事だけでは、「あの人は研究に熱心だ」といった傾向を毎回考え直すことになる。そこで複数の記憶を根拠に、より抽象的な振り返りを作る。論文では重要さの累積が150を超えると実行し、振り返りには根拠にした記憶への参照を残した。

計画は、日単位の予定を時間・分単位の行動へ分解し、新しい観察に応じて更新する。たとえば会話で招待された出来事が記憶に残り、相手との関係を捉える材料となり、当日の行き先に反映される。過去の保存、意味の整理、未来の予定が一続きになる。

## 比較実験で測ったのは、行動の人間らしさ

構成要素を外す比較実験では、すべてを備えた構成のTrueSkill平均が29.89で最も高く、振り返り、計画、記憶を順に外すと値が下がった。評価者が回答をどれだけ人間らしく納得できるかを順位付けした結果であり、事実の正確さや仕事の成功率を直接測った値ではない。

人が書いた比較用回答は22.95だった。この条件で完全構成が上回っても、AIが人間一般より優れた社会判断をするという比較にはならない。構成を外したときに一貫した振る舞いが弱まったことが、記憶と計画を分けて設計する根拠になる。

論文§6.5の評価。TrueSkillの平均μが高いほど、この実験で人間らしいと評価された

| 構成 | 平均 μ |
| --- | --- |
| 完全構成 | 29.89 |
| 振り返りなし | 26.88 |
| 振り返り・計画なし | 25.64 |
| 記憶・振り返り・計画なし | 21.21 |
| 比較用の人の回答 | 22.95 |

## 業務へ応用するなら、記録と仮説を混ぜない

編集部が業務エージェントへ応用するなら、「テストが失敗した」という記録、「依存関係が原因かもしれない」という仮説、「次に依存ファイルを比較する」という計画を分ける。論文の記憶設計を参考に、仮説から元の記録へ戻れるようにすると、誤った要約だけが残る問題を調べやすい。

価格や権限のように変わる情報には、確認日と更新条件も必要になる。何を保存したか以上に、今の判断へなぜその記憶を使ったかが分かる設計にする。検索の理由を追い、古い仮説を訂正できることが、記憶を行動へつなぐための実用的な出発点になる。

## 制約と未検証範囲

- 25体が動く仮想環境と人間らしさの評価を扱う研究。現実の人の行動予測や業務の正確性を保証する結果ではない。
- 編集部は公開論文と公式リポジトリを調査し、シミュレーションを再実行していない。個人の履歴を保存する製品では、保存範囲・同意・訂正や削除の仕組みを別途設計する。
